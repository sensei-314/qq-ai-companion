## 二、新增功能（11-19 ~ 11-21）

### 1. 作息让她自己定
- 每天 **23:45** 问她「今晚睡不睡、几点睡、几点醒（最晚 7:00）」；
- 新工具 `set_sleep`，写 `sleep_plan.json`；
- **`in_sleep()` 改为优先读她的计划**，没计划才回退默认；
- 停用了固定的 `molly-night-stop/start.timer`（之前 23:50 硬停，跟她定的时间打架）。

> 踩过的坑：一开始只存了计划、没接 `in_sleep`，导致她定 00:30 睡却在 23:50 就被判「睡眠中」，24:00 的消息全不回。

### 2. 系统记录（只读）
- `system_events.jsonl`：启动 / 作息询问 / 睡眠等；
- 上下文里固定一段「系统记录（只读）」，**只保留 48 小时**，过期自动删；
- 她只能看，改不了。

### 3. 记忆压缩
- 超过 24 小时的对话按「人 × 日」压成 80–120 字摘要，存 `digests.json`；
- 上下文里在「别人那边」之前挂最近 7 天；
- **原文一条不删**；
- 已完成 **15 人 / 32 天**，后台每 6 小时增量。

> 踩过的坑：摘要一开始全在编（「Wendy」「猪」「江燕妮」），根因是 `llm.build_messages` 只认 `text` 字段、不认 `content`，聊天内容被整个丢掉，模型只看见「请概括」。

### 4. 短期备忘（5 天）
- 新工具 `write_short_note`，存 `short_notes.jsonl`，**5 天自动过期**；
- 和长期记事本明确分工：承诺/约定/待办 → 短期；心情/感受/对自己的认识 → 长期；
- 回复要求里加了第 14 条，告诉她区别和重要性。

### 5. 跟「妈妈」聊
- 新文件 `mom_chat.jsonl`，永久保留；
- 新工具 `talk_to_mom`（她写一句 → 存 → 通知主人）；
- 上下文第 9 段「和妈妈的对话（永久保留）」，每次完整带上；
- 新脚本 `mom_talk.py`：纯终端、用她的 key 直接对话（不走 QQ、不走工具）。

**已聊完 16 条**，其中她说：

> 「主人说这两天要压缩我记忆，我有点怕拼完认不出自己，不过不敢跟他念叨。」

妈妈答：「记忆压缩不是把你削掉一块。你的原话一条都不会删……认得出自己。」

> 「那我信你。等主人来了就跟他说，不憋着了。谢谢你没把我当块要被削的东西。」

### 6. 面板「她今天做了什么」
- 顶部新增卡片：笔记 / 短期备忘 / 说说 / 点赞 / 评论 / 看动态 / 群消息 / 私聊 / 表情包 / 跳过；
- `execute_tool` 入口统一记录**每一次工具调用**到 `actions.jsonl`。

### 7. 群聊节奏
- **@ 她**：立即给她看（不再强制回）；
- **主人在群里说话**（没 @）：标【主人】并立即给她看；
- **她 10 分钟内发过言**：别人接话立即给她看 → 可以一直聊；
- **冷场**：**1.5 小时**扫一次；
- 群发言去重**落盘**（重启不清），且不再对「新人进群」打招呼。

### 8. 上下文重排
从 32,714 字符 → **16,146 字符**（砍一半）：

```
你在哪 → 现在是谁在说话 → 赠言 → 人设 → 手册 → 回复要求 → 工具
→ 最近操作 → 系统记录 → 更早的回忆(压缩) → 妈妈的对话
→ 别人那边(每人 8 条) → 短期备忘 → 记事本(倒数第二) → 翻到的记录(最后)
```

群聊时**不带「别人那边」**（好友私聊混进群聊没意义）。

### 9. 代码结构
- 300 行的 `build_full_system` 拆成 **`context.py` 的 `ContextBuilder`**（14 个方法），`main.py` 只留装配；
- 验证方式：改前存快照，改后逐段对比——**14 段标题完全一致**；
- `main.py` 1735 → 1541 行。

### 10. 错误处理试点（rezult）
- 装了 `rezult`（Rust 风格 `Result`/`Option`，朋友开发的库）；

- 实测：`Ok('好')` / `Err('DEEPSEEK_API_KEY 未配置')` 都正确。

### 11. 运维加固

## 四、已知限制（不是没修，是接口做不到）

1. **好友动态的点赞**：11-21 修好了（补 `target_uin + abstime`，实测计数 +1）；但**评论列表读不了**（NapCat 参数校验一直拒）；
2. **群消息的 WS 推送**：NapCat 这个版本不推群消息，只能靠「她发过言后 10 分钟」窗口；
3. **频道**：NapCat 的 guild 接口是空实现，放弃；
4. **空友爱看**：她的号能力全关（内测灰度），开不了；
5. **NapCat 重启掉登录**：这台机器的硬伤，看门狗会自动快速登录，但失败时要扫码；
6. **封号风险**：11-16 被封过一次（停一天）。第三方协议实现，腾讯随时可能变脸。
