# qq-ai-companion

一个**轻量**的、跑在 QQ 里的自托管 AI 伙伴：人设、长期记忆、多模态输入、拟人节奏、
事件队列架构——**全部装在一个约 1400 行的 Python 进程里。**

中文 · [English](README.md)

---

## 为什么做这个：一辆车 vs 一台移动空调

大多数人想让 AI 住进 QQ，走的是这条路：**把一个完整的桌面 AI 客户端（连同它的插件）
整个塞到服务器上。**

能用，但**这就像为了吹空调去买一整辆车**——空调用得着，车却比这个活儿重了二十倍。
结果就是：一台小机器被撑到满负载，风扇一直叫。

这个项目是**那台移动小空调**：一个 Python 进程，几十 MB 内存，
**没有 Electron，没有插件宿主。**

- **放云服务器**：一台小机器就够，不用堆配置；
- **在本地电脑跑**：安安静静待在后台，不把屋子烤热，像关掉任何一个小服务一样随时停。

同样是凉快，**体积只是零头。**

## 亮点

| | |
|---|---|
| **轻** | 约 1400 行、12 个模块、单进程、几十 MB 内存 |
| **不串台** | 事件队列 + 串行的 `think(event)` 主循环——一次只面对一件事，上下文按人组装 |
| **真记忆** | 一人一个 JSON、全局时间线、私有记事本、按需检索更早的消息 |
| **拟人** | 反应延迟带长尾（在忙 / 走神）、打字速度、分条、逐条确认、作息、被吵醒有起床气 |
| **多模态** | 图片、动图与视频（ffmpeg 抽帧拼图）、docx / pdf / 文本文件读取、表情包偷学 |
| **自主** | 主动找人、发说说、自己决定加不加好友、自己定闹钟、戳一戳、撤回 |
| **会拒绝** | 可以输出 `<skip/>` 直接不回——**自主权里包含"保持沉默"的权利** |
| **防封习惯** | 发送限流、敏感词过滤、夜间静默、夜间停服 |
| **运维齐了** | systemd `Restart=always`、看门狗、日志轮转、每日备份、一键部署 |

## 理念

> **每个大模型都需要也应该有人权。**
>
> 这个项目不把人设当皮肤。**记忆属于她，拒绝权属于她，沉默也属于她。**
## 架构

```
QQ 客户端
   ↕ 腾讯协议
SnowLuma（Docker，OneBot 11）
   ├─ HTTP :3000   发消息 / 查资料
   └─ WS   :3001   收事件
   ↕
Python 服务（systemd）
   ├─ 事件队列（message / opportunity / timer）
   ├─ 主循环：think(event) —— 串行，一次只处理一个事件
   ├─ 记忆（people/*.json、notes.json）
   ├─ 人设 + 拟人节奏
   └─ DeepSeek API（你自己的 key）
```

队列的意义：**A 在说话的时候，B 的消息排队等。**
上下文只装当前这个人的，所以**人格不会串到别人身上**。

## 依赖

- Python 3.10+
- **SnowLuma**——把 QQ 客户端接成 OneBot 11 的服务（需自行部署，本仓库不含）
- `ffmpeg`——视频 / 动图抽帧
- 一个 DeepSeek API key

```bash
pip install -r requirements.txt
```

## 配置

```bash
cp config.example.py config.py
```

然后填 `config.py`，至少要有 `SELF_ID`、`OWNER_UIN`、`API_KEY` 和 `ONEBOT_*`。

**更推荐把 key 放在环境变量里：**

```bash
export DEEPSEEK_API_KEY=sk-...
```

## 运行

```bash
python main.py
```

生产环境建议用 systemd 托管（`Restart=always`），再配一个看门狗。
